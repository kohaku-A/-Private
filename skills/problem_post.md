# 問題点を指摘するポストの知識

出典：ポスト作成テンプレ教材「Type02：問題点を指摘するポスト」の画像5枚（コンセプト解説2枚＋構成解説1枚＋実例注釈2枚）を、今後ポストを書く際に再利用できる知識として整理したもの。

## 目的

読者がうまくいっていない問題点を指摘することで、常識破壊（読者が信じている思い込みを覆す）や価値提供を行うこと。問題点を指摘すると読者の中に「新たに学ぶ思考の余白」ができるため、そこに自分のおすすめする手段や商品を誘導できる。ゴールは指摘そのものではなく、指摘の先にある解決策・商品への導線を作ること。

## 構成

問題点を指摘するアプローチには大きく3つの型がある。

1. **うまくいかない原因を指摘する**：「なぜ欲求が満たされないのか？」「なぜ苦痛を感じているのか？」を読者に問題提起する型。
2. **仮想敵の批判をする**：特定の考え方・やり方（実在の個人ではなく「〇〇と言っている人たち」という括り）を批判し、自分の立場との違いを際立たせる型。
3. **問題を放置する危険性を伝える**：今の問題をこのまま放っておくとどうなるか、というリスクを提示する型。

実例（注釈付き投稿）を分解すると、特に「①原因を指摘する」型は次の流れで構成されている。

1. **問題点の提示**：読者が思っていそうなことを「」（内的独白・セリフ調）で複数列挙する。
2. **問題点の掘り下げ**（任意）：「1日何回セールスポストしてる？」のように、読者に自分の行動を振り返らせる問いを重ねる。
3. **原因の指摘**：問題がなぜ起きるのか、根本原因を一言で言い切る（例：「単に事例不足なだけ」「そもそも売ってないだけ」）。
4. **ポテンシャルの肯定**（任意だが効果的）：「できない・わからないはあなたのセンスや才能がないわけじゃない」と読者を安心させる一文を挟む。
5. **解決策の提示**：具体的な行動やチェックリストの形で示す。「簡単そうに見せる」言い回し（「単に〇〇なだけ」「知らないなら集めてくればいい」）を使うとハードルが下がる。
6. **理想の状態を見せる**（任意）：解決した後にどんな日常になるかを描写する（`skills/change_post.md`のAfter描写と接続できる）。
7. **導線への誘導／CTA**：商品・記事へのリンクや、「いいね」などのCTAで締める。

## 書き方

- **問題点は内的独白で列挙する**：「どうやって稼いでいけばいいかわからない」「売れる商品が作れない」のように、読者自身が思っていそうなセリフを「」で複数並べると、自分ごと化しやすい。
- **原因は一言に集約する**：「〇〇不足なだけ」「そもそも〇〇してないだけ」のように、シンプルな一文で言い切ると説得力が出る。原因を複雑に説明しすぎない。
- **仮想敵を立てる場合は考え方・傾向を批判し、個人は攻撃しない**：「〇〇と言っている人たち」のような括りで書き、特定個人が特定されない表現にする。
- **ポテンシャルの肯定でフォローを入れる**：問題点や原因の指摘だけで終わると読者を責めているように読めてしまう。「センスや才能の問題じゃない」という一文を挟むことで、指摘が攻撃ではなく救済として機能する。
- **解決策は「簡単そう」に見せる**：「知らないなら集めてくればいい」「それだけ」のように、行動のハードルを下げる言い回しを使う。ただし実際に簡単でないことを誇張して「簡単」と書かない（注意点を参照）。
- **解決策は抽象論で終わらせず具体的なチェックリストにする**：「固定ポストには何があるか」「プロフのリンクはどこに繋がっているか」のように、読者がすぐ行動に移せる粒度で書く。
- **問題点の掘り下げで読者に自問させる**：「それ、今もちゃんとやってる？」のような一言を挟むと、読者が自分の状況を振り返るきっかけになり、その後の解決策が刺さりやすくなる。

## テンプレート

### 基本テンプレート（問題点列挙→原因→解決策）
```
「[問題点の内的独白1]」
「[問題点の内的独白2]」
「[問題点の内的独白3]」

これらの
「[問題点の共通項]」系の問題って、
単に"[原因]"だと思うんだよね

――――――――
[問題点1]のであれば
[解決策の具体的チェックリスト（3〜5項目）]
をみたらいい。
――――――――

――――――――
[問題点2]のであれば
[解決策の具体的チェックリスト（3〜5項目）]
をみたらいい。
――――――――

「できない・わからない」はあなたのセンスや才能がないわけじゃない。
単に"[原因]"だけ。

知らないなら[原因を埋める行動]をすればいい。

[導線へのリンク／CTA]
```

### 問いかけ深掘り型テンプレート（単一テーマを掘り下げる版）
```
[核心を突く問い]（例：そもそも"売るモノ"ある？）

[問題点の掘り下げ質問を複数、テンポよく畳みかける]
（例：1日何回セールスポストしてる？／固定ポストに飛ばす工夫はある？）

もしかして、[読者が陥っていそうな勘違い]って勘違いしてない？

いい？
[解決策・心構えを短く言い切る]（例：最初から綺麗に売ろうとするな）

[解決策の詳細・具体的な行動指針]
```

## 注意点

- **仮想敵批判は個人攻撃にしない**：実在の個人を名指しで批判・中傷しない。考え方や傾向への言及にとどめ、誹謗中傷や特定個人への攻撃と受け取られる表現は避ける。
- **指摘だけで終わらせない**：問題点・原因の指摘が強すぎると、読者を責めているだけの説教くさい投稿になる。必ず「ポテンシャルの肯定」や「解決策」とセットで使う。
- **原因の単純化に注意する**：「単に事例不足なだけ」のように言い切ると説得力が出る一方、実際には他の要因が絡むケースを捨象してしまう。読者に誤った安心感（これさえやれば大丈夫という過信）を与えすぎないよう、断定のトーンは内容の確からしさに応じて調整する。
- **「簡単そうに見せる」と実態のギャップに注意する**：ハードルを下げる言い回しは有効だが、実際には簡単でないことを「簡単」と書くと、読者が行動してみて失望し信頼を損なう。
- **商用リンクに誘導する場合は広告表記を明示する**：実例でも `#ad` タグを使用している。アフィリエイトや自社商品への導線を貼る場合、広告であることが読者に分かる表記を入れる。
- **他資料との住み分け**：
  - `skills/change_post.md`（Before/After型）は読者の「感情の変化（憧れ）」を狙うのに対し、この問題点指摘型は「読者の思考の隙間（学びの余白）を作り、そこに解決策や商品を差し込む」のが狙い。
  - 手順6「理想の状態を見せる」の部分は、change_post.mdのAfter描写のテクニックをそのまま流用できる。
  - `skills/education.md`の「現状維持マインド→成功者マインド」の構造とも近いが、education.mdは思考・価値観全体の教育、この資料は個別の問題点に対するピンポイントな指摘と解決という点で粒度が異なる。
