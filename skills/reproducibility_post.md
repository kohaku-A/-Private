# 再現性を伝えるポストの知識

出典：ポスト作成テンプレ教材「Type04：再現性を伝えるポスト」の画像5枚（コンセプト解説1枚＋心理的な壁の解説1枚＋構成解説1枚＋過去の平凡さの解説1枚＋実例注釈1枚）を、今後ポストを書く際に再利用できる知識として整理したもの。

## 目的

Type01（理想）→Type02（問題点）→Type03（解決策）が伝わっても、読者の中には最後にもう一つの壁が残る。「それって、発信者だからできたのでは？実績や強みがゼロの自分には難しいかも…」という壁である。再現性を伝えるポストは、この壁を崩し「自分にもできそう」と思わせることを目的とする。**「自分にもできそう！と思えてようやく人は動く」**——理解と納得だけでは人は動かず、再現性の実感があって初めて行動（購入・フォロー・実践）に移る、という前提に立つ。

## 構成

再現性を伝える技法は3つある。

1. **過去の平凡さを語る**：発信者自身が、今の読者と同じように何者でもなかった過去を語る。
2. **第三者のうまくいった事例を語る**：発信者以外の人物（購入者・クライアント等）が成果を出した事例を語る。
3. **成果報告や口コミを紹介する**：実際に届いた感想・成果報告をそのまま見せる。

これらを使うと、読者の中で次のような思考の変化が起きる。

- 「〇〇さんも私と同じような状態だったんだ！」（発信者との共通点の発見）
- 「〇〇さん以外にもそのノウハウでうまくいってるんだ！私にもできるかもしれない！」（自分以外の再現例による裏付け）

### 過去の平凡さの3カテゴリ

「過去の平凡さを語る」は、次の3つのカテゴリに分けて具体化できる。

- **結果が出ていなかった過去**：稼げなかった、太っていた、など数字や見た目で分かる平凡さ。
- **マインドが整っていなかった過去**：心構え・思考の面での未熟さ。
- **能力・資質が足りなかった過去**：努力できなかった、才能がなかった、など能力面の平凡さ。

実例（注釈付き投稿）では、この「過去の平凡さ」を自分自身のエピソードとして描いた投稿に、**第三者（クライアント）の事例を引用リツイートの形で接続**しており、「発信者の過去→第三者の現在→読者の未来」という時間軸を跨いだ再現性のストーリーになっている。

## 書き方

- **読者の「言い訳」をそのまま言語化する**：「才能がないよ…」「勇気がないよ…」「努力できないよ…」「時間がないよ…」「スキルがないよ…」「実績がないよ…」「強みがないよ…」「お金がないよ…」といった読者の心の声を先取りして書くと、「わかってくれている」という信頼を得やすい。
- **過去の自分をこの言い訳リストの当事者として描写する**：単に「昔は大変だった」ではなく、上記の言い訳のどれかに実際に当てはまる具体的なエピソードとして描く（例：「1部も売れなかったらどうしよう…」というビビりだった過去）。
- **第三者の事例は、自分の過去の弱さと重なる人物を選ぶ**：発信者の過去の弱さと共通点のある第三者（購入者・クライアント）を選ぶと、「発信者→第三者→読者」という再現性の連鎖がより伝わる。
- **感想・成果報告はスクリーンショットでそのまま見せる**：`skills/recommended_method_post.md`の社会的証明のテクニックと同じで、要約より実物の方が信頼性が高い。
- **過去の自分の投稿を、第三者の事例に引用で繋げる**：実例のように「過去の自分のビビりエピソード」の投稿を、後から「第三者の感想」で引用する構成にすると、時間が経っても再現性のストーリーが積み重なっていく資産になる。

## テンプレート

### 基本テンプレート（過去の平凡さ＋第三者事例の接続）
```
[第三者（クライアント・購入者）]の挑戦を見てると、
[具体的な弱さのエピソード]してた[期間]前の自分を思い出す。

「[言い訳1]…」
「[言い訳2]…」
「[言い訳3]…」

なんて不安がいっぱいやったなぁ。

そんな過去の私と同じような不安を抱えながらも、
最前線で挑戦してる[第三者]はマジでかっこいいです。私の誇り。

何かに向かって頑張る人、マジで大好きやし絶対に勝たせる。
私が保証する。

[第三者の感想・成果報告のスクリーンショットを引用で添える]
```

### 言い訳先回り型テンプレート（読者の弱さをそのまま言語化する版）
```
「[才能がないよ…]」
「[勇気がないよ…]」
「[努力できないよ…]」
「[時間がないよ…]」

そう思ってる人にこそ伝えたいんやけど、

私にも[過去のカテゴリ：結果が出ていなかった／マインドが整ってなかった／能力が足りなかった]過去がある。

[具体的なエピソード]

それでも[今の状態]になれたのは、
[推奨手段・仕組み]のおかげ。

だから、今[言い訳]って思ってるあなたにも、
同じようにできる。
```

## 注意点

- **過去の弱さの描写は誇張しすぎない**：`skills/change_post.md`の「Beforeを描きすぎない」と同じ注意が当てはまる。誇張は不自然さ・痛々しさにつながる。
- **第三者の事例・感想は実在のものだけを使う**：捏造・誇張した感想を作らない。個人情報は本人の許可なく公開しない、または加工する（`skills/recommended_method_post.md`と同様の注意）。
- **「言い訳フレーズ集」は共感の材料として使い、読者を見下すトーンにしない**：読者の言い訳を列挙する目的は「わかってくれている」という信頼構築であり、揶揄や説教のニュアンスにならないよう気をつける。
- **時系列や文脈を捏造しない**：過去の自分の投稿と第三者の事例を接続する際、実際に起きた順序・関係性の範囲で書く。
- **他資料との関係**：この資料は`skills/recommended_method_post.md`の「説得力を補強する事例の使い方」（自分自身の事例／第三者の事例／成果報告の3技法）をさらに掘り下げたものにあたる。実際に書く際は、recommended_method_post.mdの「スピード・平凡さ・簡単さ」を強調するポイントと、この資料の「言い訳フレーズ集」「過去の平凡さの3カテゴリ」を組み合わせて使うとよい。
- **`identity/my_offer.md`・`skills/my_position.md`・`skills/values.md`を踏まえる場合**：「実績や強みがゼロ」という煽り気味の自己卑下表現は、`skills/values.md`の「努力アピールにしない」「感動演出をしない」というルールと衝突しやすい。このプロジェクトで使う際は、誇張のない誠実な温度感（「苦しいものは苦しい」という事実ベースの記述）に抑え、`skills/my_position.md`が否定する「実績を偽って、強い口調で煽る発信」にならないよう注意する。
