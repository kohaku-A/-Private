# Xポスト分析

X（旧Twitter）の投稿・スレッドのパフォーマンスを、内容面（何を書いたか）と数値面（どう反応されたか）の両方から読み解き、次に何を変えれば良くなるかを具体的に提案するためのスキル。

投稿は単発で見ても「良い/悪い」の判断がつきにくい。だからこそ、複数投稿を横並びで比較し、どの要素が数字を動かしているかを相関的に見ることが分析の核になる。可能な限り、単発の感想ではなく複数投稿間の比較から傾向を導き出すこと。

## 入力データの扱い方

ユーザーからのデータは以下のいずれかの形で来ることが多い。

- チャットに直接貼り付けられた投稿本文＋数値（「いいね120、RT30、返信5、インプレッション5000」など）
- X本体からエクスポートしたCSV/JSON（列名は `text`, `likes`, `retweets`/`reposts`, `replies`, `impressions`, `created_at` などが典型だが表記ゆれがある）
- スクリーンショットの説明（数値をユーザーが書き起こしている場合はそのまま使う）

想定するフィールド（すべて揃っていなくてよい。無い指標は「データなし」として分析から除外し、その旨を明記する）：

| フィールド | 説明 |
|---|---|
| 投稿本文 | 必須。スレッドの場合は各ツイートを順番に保持する |
| いいね数 | エンゲージメントの主指標 |
| リポスト数 | 拡散力の指標 |
| 返信数 | 議論・反応の深さの指標 |
| インプレッション数 | あれば必ずエンゲージメント率の分母に使う |
| 投稿日時 | あれば曜日・時間帯の傾向分析に使う |
| メディア有無（画像/動画/リンク） | あれば内容傾向分析の軸に使う |

投稿が1件しかない場合は、比較対象がないため「一般的にエンゲージメント率が高いとされる水準との比較」や「文章構造・トーンの評価」中心の分析にとどめ、断定的な傾向論は避ける。3件以上ある場合は横断比較を積極的に行う。

## ワークフロー

1. **データの整形** — 受け取ったデータを投稿単位のテーブル（本文＋各指標）に整形する。CSV/JSONファイルが渡された場合は `scripts/analyze_engagement.py` を使って定量集計を行う（使い方は後述）。
2. **定量集計** — 投稿ごとのエンゲージメント率を計算し、投稿群の中での相対的な強弱を出す。
3. **内容分析** — 傾向分析・感情分析・トピック抽出を行う（詳細は下記）。
4. **エンゲージメント傾向分析** — 内容面の特徴と数値の強弱を突き合わせ、何が効いていそうかを言語化する。
5. **改善提案** — 具体的で次の投稿に即使えるアクションに落とし込む。
6. **レポート出力** — `references/report_template.md` の構成に沿ってまとめる。

## 各分析観点

### 傾向分析（内容の全体像）
投稿群を眺めて、話題のジャンル（雑感、告知、ノウハウ共有、質問、実況など）、文体（断定調/問いかけ調/カジュアル/フォーマル）、長さ、頻出する言い回しや構成パターンを拾う。単発の特徴ではなく「このアカウントらしさ」として繰り返し現れるものを優先して指摘する。

### 感情分析
各投稿のトーンを（例：ポジティブ／ネガティブ／中立／怒り／ユーモア／共感訴求など）ラベリングし、そのトーンとエンゲージメントの関係を見る。「ポジティブな投稿の方が伸びている」のような単純な結論を急がず、トピックや文脈と絡めて解釈する。感情の強さ（断定的か控えめか）も観察対象に含める。

### トピック抽出
投稿群から具体的な話題・キーワード・ハッシュタグを抽出し、頻度や併出関係をまとめる。可能であれば話題をいくつかのクラスタ（例：「製品の使い方」「業界ニュースへの反応」「個人的な近況」）に分類する。

### エンゲージメント傾向分析
数字の裏側にある「なぜ」を探る工程。以下の観点で内容特徴と数値を突き合わせる。

- **エンゲージメント率** = (いいね + リポスト + 返信) ÷ インプレッション（インプレッションが無い場合は算出できない旨を明記し、絶対数での比較に切り替える）
- 投稿の長さ・構成（1文完結 vs スレッド）とエンゲージメントの関係
- 画像・動画・リンクの有無との関係
- 投稿時間帯・曜日との関係（データがあれば）
- 問いかけ・CTA（コールトゥアクション）の有無との関係
- 突出して伸びた投稿・沈んだ投稿を個別に取り上げ、他と何が違うかを具体的に指摘する

### 改善提案
分析結果から逆算して、次の投稿で試すべき具体的なアクションを3〜5個程度に絞って提示する。「もっとエンゲージメントを意識しましょう」のような抽象論ではなく、「〇〇系の投稿は反応が薄いので頻度を下げる」「問いかけで終わる投稿は返信数が平均の2倍なので増やす」のように、このアカウント固有のデータに基づいた提案にする。

## レポート出力形式

特に指定がなければ、`references/report_template.md` のフォーマットに従ってレポートを作成する。投稿件数が少ない（1〜2件）場合は「エンゲージメント傾向分析」セクションを比較ではなく評価中心の内容にしてよい。

## scripts/analyze_engagement.py の使い方

複数投稿をCSVまたはJSONで受け取った場合、この集計スクリプトでエンゲージメント率の計算・ソート・基本統計（平均・中央値・最大/最小）を先に済ませてから内容分析に進むと効率的。

```bash
python skills/x-post-analyzer/scripts/analyze_engagement.py --input posts.csv
python skills/x-post-analyzer/scripts/analyze_engagement.py --input posts.json --top 5
```

入力ファイルの列名/キー名は `text, likes, reposts (retweets可), replies, impressions, created_at` を想定しているが、多少の表記ゆれ（`retweet_count` など）は自動で吸収する。対応できない列名がある場合はエラーメッセージに従ってヘッダーをリネームする。

出力はJSON（標準出力）で、各投稿のエンゲージメント率・全体統計・エンゲージメント率上位/下位の投稿を含む。この結果を土台にして、内容分析と統合したレポートを書くこと。
